# /inbox — входящие команды

Комментарий человека — комментарий без маркера `<!-- harness -->` в теле (харнес работает от тех же аккаунтов, что и люди,
поэтому различаем по маркеру, а не по автору). Обрабатывай только комментарии участников из `.harness/config.toml`.

## 1. Ответы на вопросы
```bash
gh issue list -R AIProgramIngeneering2026/team-gambit --label question --state open --json number,title,labels,url
gh issue view <N> -R AIProgramIngeneering2026/team-gambit --comments
```
Для каждого вопроса — последний человеческий комментарий после последнего комментария харнеса:
- `/answer A` или `/answer <текст>` — ответ. Любой другой человеческий комментарий тоже считай ответом, если он однозначно
  выбирает вариант; неоднозначный — уточни комментарием (одним) и не меняй ничего.
- Ответ совпал с предположением — в файле решения статус «принято», комментарий, метка `answered`, закрыть issue.
- Ответ другой — скилл `clarify` с этим issue (решение «заменено», спецификация, перепланирование задач), затем метка `answered`.
- Вопрос `needs-human` + `/approve` — снять `needs-human` и `blocked` у связанных задач, продолжить по варианту из вопроса.

## 2. Запросы изменений
Открытые issues `change-request` без метки `triaged` → скилл `clarify #<N>` (в автономном режиме он не задаёт вопросов,
а комментирует и ставит предположения).
