# Как мы работаем

## Задачи

- Любая работа начинается с issue. У каждого issue есть исполнитель.
- Если за 48 часов до срока практики по задаче нет PR, любой участник может её перехватить — написав об этом в issue. Задача засчитывается тому, кто её сделал.

## Ветки

Формат: `<тип>: <что изменилось>`, описание на русском, коротко. Тип коммита описывает изменения именно этого коммита и может отличаться от типа ветки: в ветке `feat/…` коммит с тестами получает тип `test`, с правкой документации — `docs`. Тип ветки описывает задачу целиком.

При **Squash and merge** в `main` попадает один коммит с названием PR, поэтому тип в названии PR — основной тип задачи, как у ветки.

Примеры:
- `feat: создание задания на бэктест с ключом идемпотентности`
- `test: негативные тесты на переходы из терминальных состояний`
- `fix: отклонять переход из терминального состояния`
- `docs: сценарии и жизненный цикл Job`

Один коммит — одно логическое изменение. Сообщения вроде «fix», «правки», «wip» в `main` не попадают.

## Pull Request

- Один PR — одна задача. Большую задачу дробим на несколько PR.
- Название — в формате коммита.
- В описании: что сделано, как проверить и `Closes #<номер issue>`.
- Прямой push и force push в `main` запрещены. В `main` — только через PR.

## Review

- Каждый PR одобряет хотя бы один участник, кроме автора.
- По умолчанию проверяем по кругу: Девятов → Савенков, Беляев → Девятов, Савенков → Беляев. Если ревьюер не может — берёт любой другой.
- Ревьюер отвечает в течение 24 часов.
- Review — по сути: вопросы, ошибки, несоответствие требованиям. «LGTM» без комментариев не считается.
- **Request changes** — если без правки нельзя вливать. **Approve** с комментариями — если замечания можно вынести в отдельный issue.
- Вливает автор после одобрения, через **Squash and merge**.
- Если одобрить некому — второй участник пропал, — одобрение даёт проверяющая команда из перекрёстного review.

## Definition of Done

Задача сделана, когда:

- [ ] PR влит в `main` с одобрением другого участника;
- [ ] выполнены все критерии приёмки из issue и `docs/requirements.md`;
- [ ] для кода — есть тесты, включая негативные, CI зелёный;
- [ ] документация обновлена, если изменилось поведение или контракт API;
- [ ] issue закрыт.

Работа по практике должна быть в `main` до срока: проверяется только то, что влито.
