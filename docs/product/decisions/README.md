# Решения по требованиям

Здесь — ответы команды на вопросы о бизнес-требованиях и предположения агентов, которые ждут подтверждения.
Это часть спецификации: агенты читают её раньше остальных документов (скилл `decision-protocol`).

- Один файл — одно решение: `<номер issue>-<slug>.md`. Номер issue с меткой `question` или `change-request` — идентификатор решения `D-<номер>`.
- Статусы: **предположение** (агент выбрал сам, ждёт ответа), **принято**, **заменено D-…**, **отклонено**.
- Решение меняет поведение — в том же PR правятся затронутые документы: `requirements.md`, `api/openapi.yaml`, `tool-contract.md`, `architecture.md`, ADR.

Как ответить на вопрос агента: комментарий `/answer A` (или свой вариант) в issue — его подхватит `/inbox`;
либо `/interview` в Claude Code. Как предложить изменение самим: issue по шаблону «Изменение требований» или `/clarify <текст>`.

## Формат
```markdown
# D-23. Окно сигнала по умолчанию
- **Статус:** предположение
- **Источник:** issue #23; предположение агента в PR #25
- **Вопрос:** …
- **Решение:** …
- **Варианты:** A — … (выбран), B — …
- **Влияние:** docs/tool-contract.md §6, docs/api/openapi.yaml `SignalRequest`, issues #24, #26
```
