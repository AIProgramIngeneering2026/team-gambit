# TradeLab — инструкции для агентов

TradeLab — бэктестер торговых стратегий на дневных свечах MOEX: задание на бэктест (Job) → Dispatcher → Registry → StrategyTool → результат и текущий сигнал. Учебный командный проект курса «Программная инженерия» (команда gambit, задания — репозиторий Zadania).

## Спецификация — источник истины
Порядок: `docs/concept.md` → `docs/requirements.md` (сценарии С1–С6, критерии) → `docs/architecture.md` и `docs/adr/` → контракты `docs/api/openapi.yaml`, `docs/tool-contract.md` → код → тесты. Решения команды — `docs/product/decisions/`.
- Поведение, которого нет в спецификации, в код не попадает: сначала спецификация (скилл `spec-dd`).
- Неясно или противоречиво — протокол решений (скилл `decision-protocol`), не догадка.

## Процесс (CONTRIBUTING.md)
- Любая работа начинается с issue с исполнителем. В `main` — только через PR; squash and merge; вливает автор после review.
- Ветки `<тип>/<issue>-<slug>`, коммиты и названия PR — `<тип>: <что изменилось>` на русском; в PR — `Closes #N`.
- Рецензенты по ротации — поле `reviewer` в `.harness/config.toml`. Review — по существу, комментариями к строкам.
- Перед PR — `scripts/harness/check.sh` (тесты харнеса, ссылки в документах, OpenAPI, независимость ядра, pytest).
- Нельзя без человека: push в `main`, force-push, удаление веток, данных и ресурсов, сброс незакоммиченных изменений. Хук `scripts/harness/guard.py` это блокирует.
- Секреты — только имена переменных; значения не выводить и не коммитить.

## Код
- Python 3.11+, uv, pytest. Ядро — `src/tradelab/domain/`: без импортов FastAPI, SQLAlchemy, httpx и драйверов БД.
- Переходы Job проверяет сам Job; Dispatcher не знает конкретных Tool; новая стратегия — регистрацией в Registry.
- Деньги и цены — Decimal. Тесты называются по критериям: `test_c1_2_…`, злодейства — `test_z3_…`.
- Документы и сообщения — на русском, идентификаторы — на английском.

## Харнес (docs/harness/README.md)
| Команда | Что делает |
|---|---|
| `/practice [pN]` | Очередная практика целиком: задание → спецификация → задачи → свои PR → review → вливание → аудит → отчёт |
| `/practice-status [pN]` | Состояние практики и следующий шаг каждого участника |
| `/implement-issue <N>` | Одна задача по спецификации до PR |
| `/review-pr <N> [--cross]` | Содержательное review, в том числе перекрёстное |
| `/practice-report pN` | Отчёт `teams/gambit/pN.md` в Zadania из fork |
| `/interview [pending\|тема\|feature …\|next]` | Агент спрашивает команду и записывает решения |
| `/clarify <текст\|#issue>` | Команда уточняет или меняет требование: impact analysis, решение, правка спецификации |
| `/inbox` | Ответы `/answer` и запросы `change-request` из GitHub |

Режим `HARNESS_MODE=autonomous` (запуск `scripts/harness/run.sh`) — человека нет: вопросов не задавать, действовать по протоколу решений; команды запускать по одной, без цепочек `;` `&&` `|` (разрешение проверяется для каждой части); GitHub — только через `gh`. Всё, что агент пишет в GitHub, начинается с `<!-- harness -->`.
